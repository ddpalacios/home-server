Redesign scope — how should we tackle this?

The ETL app has ~7 distinct UI surfaces (sidebar, canvas, notebook, bottom tabs, activity settings, tables/modals, header). A "full redesign" is a lot — pick the path that fits how you want to iterate.

A

Foundation first → propagate

Start with a tight design system: tokens (color, type, space, radius, shadow), reusable components (buttons, inputs, cards, tabs), and one showcase area redesigned end-to-end (e.g., the sidebar). You react. Then the same system gets applied to the rest in successive passes. Recommended — fast feedback, low risk, you see the direction before it touches everything.

B

Single big-bang pass

One design system + one redesign of every visible surface in a single spec. Faster end-to-end if I get it right; risky if the look isn't what you wanted (Azure Synapse 2.0). You'd need to commit to the visual direction up front from a mockup and live with whatever ships.

C

Per-area, no foundation

Pick one area (sidebar / notebook / bottom tabs / activity settings), redesign just that, ship, repeat. No shared system. Visually inconsistent during the journey but every change is small and reversible. Slowest path overall but lowest risk per step.
